# Jibiki v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Jibiki v1 — a bring-your-own-dictionary Japanese dictionary for Android and the web (Kotlin/Wasm), per `docs/superpowers/specs/2026-10-15-jibiki-design.md`.

**Architecture:** Kotlin Multiplatform with Compose Multiplatform UI. All logic (parsing, DB, search) lives in `commonMain` and talks to SQLite through `androidx.sqlite` driver interfaces + `androidx.sqlite.async` suspend extensions. Android uses `BundledSQLiteDriver`; web uses `WebWorkerSQLiteDriver` backed by our own worker wrapping `@sqlite.org/sqlite-wasm` with the `opfs-sahpool` VFS; JVM unit tests use `BundledSQLiteDriver`.

**Tech Stack:** Kotlin 2.4.20, Compose Multiplatform 1.12.1, AGP 9.4.1 (`com.android.kotlin.multiplatform.library` for libraries, `com.android.application` for `androidApp`), Gradle 9.8 wrapper, JDK 21, kotlinx-coroutines 1.11.0, kotlinx-serialization 1.11.0, androidx.sqlite 2.7.1 (`sqlite`, `sqlite-async`, `sqlite-bundled`, `sqlite-web`), npm `@sqlite.org/sqlite-wasm` 3.53.4-build2, npm `fflate` 0.8.3.

## Global Constraints

- Targets: Android (minSdk 26, compileSdk 37, targetSdk 36) and `wasmJs` browser. Every non-UI module also has a `jvm()` target used only for tests.
- Web: Firefox 120+ and Chromium; no COOP/COEP headers required (use `opfs-sahpool`, never the `opfs` VFS).
- No term/definition/kanji dictionary data in the repo or app. Only bundled data: EDRDG RADKFILE (CC BY-SA 4.0) with attribution. Test fixtures contain invented entries only.
- License: GPL-3.0 (deinflection rules ported from Yomitan).
- Yomitan dictionary format 3 only.
- Package root: `dev.jibiki`.
- No `Co-Authored-By` or AI attribution in commits. Commits are blocked weekdays 07:00–18:00 by a user hook; when blocked, leave changes uncommitted and report.
- Search p95 < 100 ms; JMdict import < 3 min on desktop web.

### Task B4: Deinflector (port of Yomitan `japanese-transforms.js`)

**Files:** `core/japanese/src/commonMain/.../{JapaneseTransforms.kt, Deinflector.kt}`, `DeinflectorTest.kt`

**Produces:**
```kotlin
data class Deinflection(val text: String, val conditions: Set<String>, val reasons: List<String>)
class Deinflector(rules: List<TransformRule> = JapaneseTransforms.all) { fun deinflect(source: String): List<Deinflection> }
data class TransformRule(val name: String, val inflected: String, val deinflected: String, val conditionsIn: Set<String>, val conditionsOut: Set<String>)
object Conditions { fun matches(termRules: Set<String>, required: Set<String>): Boolean }  // empty `required` matches anything; maps Yomitan part-of-speech rules v1/v5/vk/vs/vz/adj-i to condition families (v5 covers v5*, etc.)
```
Algorithm (Yomitan's): BFS from `(source, conditions=∅, reasons=[])`; for each result and each suffix rule where `text.endsWith(inflected)` and (`conditions` empty or intersects `conditionsIn`), produce `(text.dropLast(inflected.length)+deinflected, conditionsOut, [name]+reasons)`; skip already-seen `(text, conditions)`; the original is included with empty conditions.

Port the full rule table from Yomitan `ext/js/language/ja/japanese-transforms.js` (GPL-3.0; keep the file header attribution).

Test cases: `食べなかった` yields `食べる` with conditions containing `v1` and reasons `["negative","past"]` (order per Yomitan naming); `行った` → `行く` (v5k-s via `って`); `高くない` → `高い` (adj-i); `勉強させられた` → `勉強する` (vs); `来ない` → `来る` (vk); `読んでいる` → `読む`; input `食べる` includes itself with empty reasons.

